# งานส่งต่อ: ตรวจสต๊อก BigSeller และเตรียมรอบเก็บตกของ TIMES POS

ไฟล์นี้มาจาก session ที่ดูแลโค้ด TIMES POS (repo `Evasi0m/TIMES_POS`) เจ้าของร้านแนบมาให้คุณทำต่อ
คุณมี Chrome ที่ล็อกอิน TIMES POS (super admin) และ BigSeller ไว้แล้ว

**กฎสำคัญ:** งานนี้เป็นงาน **ตรวจและรายงาน** ห้ามกดดาวน์โหลดรอบเก็บตก ห้ามแก้สต๊อกใน BigSeller และห้าม export รอบปกติด้วยมือ จนกว่าเจ้าของร้านจะยืนยัน

---

## 1. บริบท

### ระบบ Export ไป BigSeller
- POS คือตัวเลขสต๊อกจริง ส่วน BigSeller (คลัง **TIMES STOCK**) ไม่มี API ให้เขียน
- POS จึงส่งการเปลี่ยนแปลงเป็นไฟล์ Excel Stock-In / Stock-Out จากปุ่ม **สินค้า → Export ไป BigSeller** (ใช้ได้เฉพาะ super admin)
- ส่งทุกช่องทาง ทั้งหน้าร้าน, TikTok, Shopee, Lazada, Thaimart, Facebook เพราะร้านส่งของนอก BigSeller ทำให้ BigSeller ไม่ตัดสต๊อกเอง
- แต่ละรอบ export บันทึกไว้ในตาราง `bigseller_export_batches` ช่วง `(from_movement_id, to_movement_id]` ทำงานเป็น cursor รอบใหม่เริ่มต่อจากรอบก่อน
- มี **scheduled task** export ทุก 2 ชั่วโมง แล้ว import และ confirm ไฟล์ใน BigSeller ให้อัตโนมัติ

### จุดรีเซ็ต 18 พ.ย. 2569
- คลัง TIMES STOCK ถูกตั้งให้ตรงกับ POS ณ **stock_movements id 17576**
- มีรอบเครื่องหมาย `reset-2026-11-18` (batch id 3, from = to = 17576) ไว้บอกจุดนี้
- รายการที่ id ≤ 17576 รวมอยู่ในการตั้งใหม่แล้ว **ห้ามส่งซ้ำ** ไม่งั้นสต๊อกจะถูกตัดสองรอบ

### สิ่งที่เพิ่งเปลี่ยนใน POS (PR #23, #24 merge แล้ว, migration 092 รันแล้ว)
- ตาราง `bigseller_export_batches` มีคอลัมน์ `kind` (`normal` | `catchup`) และ `carried_from` เพิ่ม
- RPC `bigseller_export_state` และ `bigseller_record_batch` นับเฉพาะรอบ `kind = 'normal'`
- `bigseller_record_batch` รับพารามิเตอร์ `p_carried_from bigint DEFAULT NULL` เพิ่ม (มีค่า default จึงใช้กับ client เดิมได้)
- **Carry-forward:** ทุกรอบปกติจะลองส่งสินค้าที่รอบก่อนหา SKU ไม่เจอซ้ำ เดิมสินค้าพวกนี้หายไปเงียบๆ
- **รอบเก็บตก:** ปุ่ม "คำนวณรายการเก็บตก" ทำได้ครั้งเดียว (RPC `bigseller_record_catchup`) ไม่ขยับ cursor และนับเฉพาะหลังจุดรีเซ็ต ตอนนี้คาดว่าเหลือแค่สินค้าที่หา SKU ไม่เจอในรอบ 8 และ 10
- **ถ้า scheduled task เรียก RPC หรือเขียนตารางเองโดยไม่ผ่านหน้าเว็บ** ให้เช็กว่ายังทำงานได้หลัง migration 092

## 2. งานที่ 1: หาสาเหตุ AE-1200WHL-5A (อ่านอย่างเดียว)

**ฝั่ง POS:** ยอดขายรุ่นนี้ตั้งแต่ 16 พ.ย. มีดังนี้ (qty −1 ทุกรายการ)

ดังนั้น ณ จุดรีเซ็ต (17576) POS ควรมีสต๊อก **4** และหลังจากนั้น POS ส่ง Stock-Out ไป **4** ชิ้น (batch 7: 3 ชิ้น, batch 12: 1 ชิ้น) คลังควรเหลือ **0**

**สิ่งที่ต้องตรวจใน BigSeller**
1. สต๊อก SKU `AE-1200WHL-5A` ในคลัง TIMES STOCK ตอนนี้มีเท่าไร
2. ประวัติการเคลื่อนไหวของ SKU นี้ตั้งแต่ 18 พ.ย.: ตอนรีเซ็ตตั้งไว้เท่าไร และมี Stock-Out จากไฟล์ import กี่ครั้ง กี่ชิ้น
3. ไฟล์ export รอบ 4–12 ถูก import และ **confirm** ใน BigSeller ครบไหม มีไฟล์ค้าง, ล้มเหลว, หรือมีแถวที่ถูกปฏิเสธไหม
4. listing Shopee ของรุ่นนี้ (Model ID 301885484663) ผูกกับ SKU คลังนี้ และเปิด sync สต๊อกอยู่ไหม หรือ Shopee มีสต๊อกของตัวเองแยกอยู่
5. ถ้าเจอสาเหตุ ให้เช็กด้วยว่ามีรุ่นอื่นที่น่าจะเป็นแบบเดียวกันไหม เช่น ไฟล์รอบไหนที่ไม่ได้ import

## 3. งานที่ 2: เตรียมรอบเก็บตก (ห้ามกดดาวน์โหลด)

1. เปิด TIMES POS แล้ว hard refresh ต้องเห็นข้อความในกล่องสีเหลืองว่า **"นับเฉพาะหลังจุดรีเซ็ตคลังล่าสุด"** ถ้าไม่เห็น แปลว่ายังเป็นเวอร์ชันเก่า ให้รอ deploy แล้ว refresh ใหม่ ดู deploy ได้ที่ https://github.com/Evasi0m/TIMES_POS/actions (Deploy to GitHub Pages ของ commit `94fb02b` ต้องเป็นสีเขียว)
2. ไปที่หน้าสินค้า → Export ไป BigSeller → กด **คำนวณรายการเก็บตก**
3. จดตัวเลขทั้งหมด: ช่วงที่ไม่มีรอบครอบ, ยอดขายออนไลน์ที่รอบเก่าข้าม, สินค้าที่เคยหา SKU ไม่เจอ, Stock-In, Stock-Out, หา SKU ไม่เจอ
   - **ที่คาดไว้:** 2 ตัวแรกเป็น 0 และสินค้าที่เคยหา SKU ไม่เจอประมาณ 2
   - ถ้า 2 ตัวแรกไม่ใช่ 0 แปลว่ายังเป็นเวอร์ชันเก่า **ห้ามทำต่อ** ให้รายงานกลับ
4. ถ้ามีรายการ "หา SKU ไม่เจอ":
   - คลิกช่อง Merchant SKU แล้วพิมพ์รหัสรุ่นบางส่วน เช่น `MDV-107` หรือ `AQ-230` ถ้ามี SKU ที่ตรงรุ่นจริงในคลัง ให้เลือกแล้วกด **บันทึก**
   - ถ้าไม่มี ให้จดชื่อสินค้าไว้ **ห้ามกด "ไม่ส่ง BigSeller" เอง**
5. **ห้ามกด "ดาวน์โหลด + บันทึกรอบเก็บตก"** รอบนี้ทำได้ครั้งเดียว ต้องรอเจ้าของร้านยืนยันก่อน
